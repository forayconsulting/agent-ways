## Steps

### A. Round 4 eval (in the worktree)

1. Specify commit: transcript, R24 to R27, defaults. Then predict commit: `spe/plans/r04.md` and `spe/predictions/r04.yaml`, before any harness work.
2. Freeze E to `spe/evals/configs/E-r03/`. Build F in `hooks/ways/evaluative/spe/`. Gates: lint 0 errors, Jaccard below 0.15, register shows no flags, and the root is 3,500 characters or less.
3. Make the S2 grader changes (`order_list` default in `grade.py` and the workflow `codeChecks`, wider `same_tasks`). Add the E3 fixture in `make_fixture.sh`, its checks and selftest cases in `grade_e2e.py`, and the r04 entry in `build_workflow.py`. Gates: `grade.py --selftest`, `grade_e2e.py --selftest` (now with E3 good and bad cases), and `cargo test -p ways` after regenerating the probe TSVs if the golden prompts change.
4. Dry run E-H4p, F-H5, F-E3, and E-E2. Move the personal SPE ways aside for the run. Commit the harness.
5. Full run `{round: "r04", trials: 8, e2eTrials: 6, topupCap: 0}`. Then results, the learn step, and the commits.
6. Install rule: F wins if F's text mean is at least E's minus 0.02, no task drops more than 0.15 against E, and F's E2E mean is not lower. Otherwise E stays. Restore the personal tree with the winner (backup `evaluative-spe-r03`). Run the live trigger check with `context_cap` counting. Tag `spe-r04`.

### B. Ship

7. **Push the experiment branch.** `gh auth switch --user forayconsulting`. Then `git push fork feat/spe-loop-way --tags`, so the evidence branch, tags `spe-r01` to `spe-r04`, and the spe/ folder are on the fork.
8. **PR 1 branch `feat/tools-trigger-lane`**, from `origin/main` d7e69366:
   - Apply the engine commit's changes except `tests/probes/*`.
   - One commit: `feat(engine): add a tools: trigger lane (ADR-704)`.
   - Gates: `cargo build --release -p ways`, `env HOME=$(mktemp -d) cargo test -p ways`, `make test-sim`, `WAYS_TEST_BIN=... bash tests/hooks-test.sh` (new cases pass), `uv run --with pyyaml docs/scripts/adr lint --check`, and clippy on ways and ways-core.
   - Then `git push -u fork feat/tools-trigger-lane` and `gh pr create -R aaronsb/agent-ways --base main --head forayconsulting:feat/tools-trigger-lane`.
9. **PR 2 branch `feat/evaluative-spe-ways`**, stacked on PR 1's branch:
   - Add the winning `hooks/ways/evaluative/spe/` tree with golden sidecars, the `evaluative.md` routing row, and the regenerated probe TSVs.
   - One commit: `feat(ways): add evaluative/spe, the SPE loop for plan mode and Workflow evals`.
   - Gates: worktree-binary lint `--check` on the tree, Jaccard, `cargo test -p ways` (probe samples match), and `check-register.sh`.
   - Then push, and run `gh pr create` with the body stating "Depends on #<PR1>. Includes its commit until that merges."
10. **PR bodies:** Summary, Why, Trade-off, Test plan, Not in scope. They link the fork's `spe/` folder and the prediction log as evidence. PR 2 reports the round 1 to 4 numbers. No attribution lines.
11. `gh auth switch --user chanceypraecipio`. Report both PR URLs.

### C. Live for all sessions
